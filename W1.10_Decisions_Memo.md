| # | Decision | Rationale | Owner | Status |
|---|---|---|---|---|

| 2 | **Retrieval — in-memory numpy dense + BM25 sparse + curated atomic-phrase dictionary, RRF-fused** | BM25 is non-negotiable for exact legal identifiers (case names, statutes) that no embedding reliably handles; RRF fuses the two arms over one aligned universe. | Pao | **LOCKED** |
| 3 | **Topic model — 34-topic curated taxonomy as centroid dimensions; SOFT-PRIOR bias, not hard gating** | Interpretable dimensions; bge cosine compression made the old 0.85 bar meaningless. Thresholds locked W1.7: `TOPIC_MERGE_COSINE=0.95`, `TOPIC_ASSIGN_MIN_COSINE=0.68` (chunk-level; 35→34 after one merge). | Dev0 / Sheena | **LOCKED** (W1.7) |
| 4 | **Routing — deterministic code router; Haiku removed** | Zero pre-composition LLM round-trips — empirically verified: `llm_calls_before_composition == 0` across all 10 W1.9 queries. Removes a latency/cost/failure surface from the hot path. | Pao | **LOCKED** |
| 5 | **Composition — Sonnet (claude-sonnet-4-6), streamed prose + trailing ENVELOPE** | Quality of composition matters most; streaming hides generation latency behind TTFT. `MAX_TOKENS=300` cap + Voice Card length discipline control output cost. | 6 | **Theme-as-control-signal — topics bias retrieval, never gate** | A routing error must not hide the right passage. Topics drive register/disclaimer + a soft prior; a weak/out-of-scope prior falls through to global retrieval within the universe (orphaned-content guard). | Pao | **LOCKED** |
| 7 | **Deployment — robot = front-end I/O only; off-board Service holds resident model + indexes + makes the API call** | Reachy Mini (CM4) lacks the resources for a resident 1024-dim model + indexes; Service host owns embeddings, retrieval, and the `native_sdk` API call on a clean-TLS host. | Dev0 | **LOCKED** (intent); host provisioning ongoing |

## Pilot targets (provisional, anchored to W1.9)

Source: `baseline.json` — single warmed run, **n=10**, `transport=native_sdk`, `embed_device=cuda`, `composer_model=claude-sonnet-4-6`. Entered into the **Pilot Metrics** sheet (`CJP_Pilot_Weekly_Plan_v2.xlsx`).

| Metric | Baseline (W1.9, measured) | Provisional target |
|---|---|---|
| **TTFT** (composer-start → first chunk) | p50 **1207 ms** / p95 **2087 ms** | ~1.2s p50 / ~2.1s p95 |
| **Total e2e** | p50 **8044.8 ms (8.0s)** / p95 **8928.2 ms (8.9s)** | ≤ ~8.0s p50 / ~8.9s p95 |
| **Per-stage (p50)** | input_gate 0.0 · router 164.6 · retrieval 83.2 · **composer 7790.2** ms | hold (composer-bound) |
| **Cost/query** | cached **$0.0169** · uncached-equiv **$0.0288** (voice-card caching saves **$0.0119/query**) | ≤ ~$0.017 cached |
| **Quality** (grounding, recall@k, routing, register, out-of-scope) | — | **TBD — W3.x eval harness** (not fabricated) |

**Latency shape:** ~**97%** of total e2e is the composer (7790 of 8045 ms at p50). The local path (gate + router + retrieval) is ~248 ms combined. **Perceived latency rides on TTFT** (~1.2s), since the streamed answer drives sentence-chunked TTS — so TTFT, not total e2e, is the number the user feels.

**Observations from the run (flagged, not acted on):** every one of the 10 queries saturated the dynamic cutoff at `MAX_K=12` chunks (the cutoff never bound below the ceiling), and 2 of 10 answers hit the `MAX_TOKENS=300` cap. Both are inputs to the W3.x payload/threshold sweep, not defects.

## Caveats (do not omit — these protect downstream decisions)

1. **Single warmed run, n=10, constructed query set.** The W1.9 numbers come from one warmed run of **10 queries on a CONSTRUCTED draft-query set** (`draft_queries_v1.json`) — **no official frozen set existed**. All targets here are **PROVISIONAL** until the frozen set + the W1.11 anchor exist.
2. **OPEN ITEM — blocks W1.11 (highest priority, must not slip).** The **frozen draft-query set must be DEFINED and SIGNED OFF before W1.11 tags arch-baseline.** The anchor (the W3.3 sweep comparator) will be measured on whatever query set exists at that moment — so a sloppy set permanently distorts every later comparison. **Owner: Sheena.**
3. **ENVIRONMENT PRECONDITION (standing).** The Service host requires **Avast HTTPS scanning OFF** for the venv `python.exe` (it injects an applink-incompatible OpenSSL that hard-aborts native TLS). All other Avast shields stay ON — see the documented Service-host security profile. This **recurs on ANY host running TLS-inspecting security software** (Sheena's box, the eventual Service host), so treat it as a provisioning checklist item, not a one-off.
4. **`OUT_OF_SCOPE_THRESHOLD` is provisional/uncalibrated.** The query-time out-of-scope gate (`config.OUT_OF_SCOPE_THRESHOLD=0.15`) is **distinct from the 0.68 doc/chunk assignment floor** and is not yet calibrated. Calibrate it once real queries exist (W3.x); until then, out-of-scope handling targets stay TBD.
