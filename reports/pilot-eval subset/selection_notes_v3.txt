HOW THE QUOTAS WERE COMPUTED (deterministic, reproducible)
----------------------------------------------------------
For each theme T (target 19):
  1. Consider only formats that HAVE docs in that theme ("present formats").
  2. ideal_f = 19 * (corpus_count_f_in_theme / total_docs_in_theme).
  3. Largest-remainder (Hamilton) apportionment: floor each ideal_f, then hand out
     the leftover slots one-by-one to the largest fractional remainders (ties
     broken by a fixed format order Column>Biography>Book>Speech) until the theme
     sums to exactly 19.
  4. Floor of 1 for every present format (none fell to 0 here, so no bump needed).
  5. FORCED-CELL RAISE: if a (theme,format) cell's count of forced docs EXCEEDS its
     quota, raise that cell's quota to its forced count and reduce other cells in
     the same theme by largest current quota (never below floor 1) to keep the
     theme total at 19. This fired twice:
       - Theme A: Book forced = 2 (BA009, BA027) > quota 1  ->  Book raised to 2,
         Column reduced 16 -> 15.
       - Theme E: Speech forced = 2 (SE012, SE013) > quota 1  ->  Speech raised to 2,
         Column reduced 15 -> 14.
     (Theme A carries 8 forced docs total: Column 5, Book 2, Speech 1.)

SELECTION PROCEDURE
-------------------
1. Force-include every mandatory doc (AI-governance + orphaned-topic) into its
   own (theme, format) cell first.
2. Fill each remaining cell slot deterministically by ASCENDING Article-Code order
   from that theme+format pool, skipping any doc already selected/forced.
3. No doc selected twice. Source corpus row order/content left untouched.
4. Output row order in the frozen CSV: theme (A-E), then format
   (Column, Biography, Book, Speech), then Article-Code ascending.

"ORPHANED TOPIC" — DEFINITION (unchanged)
-----------------------------------------
A substantive subject keyword appearing in <= 2 of the 1,089 docs
(singleton / near-singleton), determined by a CORPUS-WIDE CASE-FOLDED tally of the
"Keyword/s" field; person-name-only tokens are ignored. NOTE: the stored
"Keyword/s" field is NOT pre-casefolded, so the tally case-folds at counting time.
The forced orphaned docs were confirmed to resolve and their defining keywords
confirmed rare under this tally (each appears in 1 doc, except surrogacy in 2:
CC069). They are force-included even where atypical for their cell.
